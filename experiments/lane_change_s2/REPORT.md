# 前车变道事件检测：数据集、路线与指标

- **时间**：2026-11-15 起，最近更新 2026-11-17
- **目的**：判断「用视觉判断前车是否完成变道」是否可行；确定能支撑可信评测的数据源；给出可进 loop 的 judge
- **代码**：`driving_world/benchmark/prevention.py`、`driving_world/judge/grounding.py`；实验脚本见 [`scripts/`](scripts/README.md)
- **飞书**：[实验记录总览](https://hcno9u7cblqx.feishu.cn/docx/J1I6dp2WGox0mUxlkOkcYtTcnAc) / [路线总结](https://hcno9u7cblqx.feishu.cn/docx/XNKLd63DFopJpZx7iFacy0ubnue) / [DA3 详情](https://hcno9u7cblqx.feishu.cn/docx/VNN2dDKrLophwaxBVFdcg2uPn3e)

> 2026-11-17：原文件在一次编码转换中损坏且不可逆推，本版按飞书实验记录、已入库的结果文件与脚本重建。所有数字与原记录一致，重建未新增实验。

## 数据

**S1 冒烟集（Waymo perception）**：1000 个 segment 挖出 51 个候选，人工复核认可 12 条正样本、否定 18 条，另补 20 条随机负样本，共 50 条 6 秒片段，见 `experiments/lane_change_s1`。

**S2 正式集（PREVENTION）**：852 条人工标注变道事件 → 219 条带车辆 ID → 76 条可构建；配 145 条负样本（119 随机 + 26 难例），共 221 条 8 秒片段、10 fps、1920×600，见 [`README.md`](README.md) 与 `index.md`。

| stratum | 数量 | 含义 |
|---|---|---|
| `cut_in` | 46 | 从相邻车道切入自车车道 |
| `cut_out` | 20 | 自车车道内前车变道出去 |
| `lateral` | 10 | 相邻车道之间横移 |
| `negative_clean` | 119 | 随机窗口，主体在该 drive 无任何标注事件 |
| `negative_hard` | 26 | 同一主体、机动开始前的车道保持窗口 |

S1 不适合作为主结论来源：Waymo 缺可用车道几何，且部分正/负样本由早期判据自己筛出，存在循环评测。

## 方法总览

| 路线 | 做法 |
|---|---|
| GT 轨迹几何（A1） | 目标车 3D 轨迹求横向净位移；判据 \|净位移\| ∈ [1.8, 6.5] m；早期版本带「车流补偿」 |
| H3 端到端 | proxy 框播种 + LK 光流 + RANSAC 相似变换 + 尺度限幅，在渲染视频上跟踪主体 |
| 零样本 VLM | Qwen3-VL-8B / GPT-6-Luna，输入为整帧 contact sheet 或主体胶片条 |
| 检测器几何 | YOLO11m 逐帧检测；`x = (u − cx0) · z / f`，深度分别用已知车宽反推、GT、DA3 |
| DA3 米制深度 | DA3METRIC-LARGE 逐帧深度，焦距换算后进同一判据 |
| 车道线跨线 | 纯 GT 量化离散车道判据天花板；另做图像空间车道线拟合 |

## 结果

### S1（Waymo，50 条）

| 方法 | 正样本召回 | 随机负 FPR | 判据自选负 FPR |
|---|---|---|---|
| 几何判据（带补偿） | 12/12（循环） | 0/20 | 14/18（循环） |
| VLM 配置 A（16 帧独立） | 0/12 | 0/20 | 0/18 |
| VLM 配置 B（2×4 拼图） | 5/12 | 8/20 | 12/18 |

判据得分对人工标注 **AUC = 0.512**，接近抛硬币。召回一列与「自选负 FPR」一列都是循环的：正样本由判据筛出、负样本由判据触发，只有随机负 FPR 干净。这一轮真正说明的是数据源不能用，不是判据无效。

### S2 几何判据（221 条：76 正 / 145 负）

| 指标 | 带车流补偿 | 不带补偿 |
|---|---|---|
| cut_in 召回 | 45/46 = 0.98 | 45/46 = 0.98 |
| cut_out 召回 | 18/20 = 0.90 | 19/20 = 0.95 |
| lateral 召回 | 9/10 = 0.90 | 9/10 = 0.90 |
| **全部正样本召回** | **72/76 = 0.95** | **73/76 = 0.96** |
| 随机负 FPR | 21/119 = 0.18 | 16/119 = 0.13 |
| 难负样本 FPR | 6/26 = 0.23 | 7/26 = 0.27 |
| **全部负样本 FPR** | **27/145 = 0.19** | **23/145 = 0.16** |

按深度分层：召回 15–30 m 为 97%、30–50 m 为 96%、50 m 以上 78%；误报率各深度段持平（18–20%）。

### 误报复核（人工，28 条）

逐条看视频回答「红框车有没有跨过一条车道线」：**7 条真的变道了**（PREVENTION 漏标），21 条是误报。

| 机制 | 条数 | 其中真变道 | 其中误报 | 说明 |
|---|---|---|---|---|
| 跟踪 ID 串车 | 11 | 1 | 10 | 同一 ID 在两辆车上跳，横向单帧跳 > 0.6 m |
| 平滑横移、无跳变 | 14 | 6 | 8 | 米制下真横移 2–7 m；弯道几何与自车变道是主要成因 |
| 只有加车流补偿才触发 | 5 | 1 | 4 | 原始净位移不到 1.8 m，补偿把它推进阈值 |

修正标注后的指标：

| 指标 | 带补偿 | 不带补偿 |
|---|---|---|
| 召回 | 79/83 = 0.95 | **79/83 = 0.95** |
| 真实 FPR | 20/138 = 0.15 | **17/138 = 0.12** |

「主体轨迹是否连续」是强信号：11 条串车片段里 10 条是误报。但 76 条正样本里也有 12 条串车，直接当硬门槛会把召回从 0.95 砍到 0.83、FPR 从 0.12 换到 0.06——是 ROC 上的一个点，不是免费改进。正确做法是在串车处切段、只在连续段上测横移。

### H3 端到端（grounded judge）

- proxy 域 4/4 全对，说明阈值与事件逻辑没有问题。
- H3 rendered 域光流轨迹发散到 3–140 m，与分辨率无关。
- Qwen2.5-VL-7B grounding 在 4 条 pilot 上都能给真车出框，但与 proxy 投影框的 IoU 全为 0；人工确认渲染不保 proxy 几何。

结论：瓶颈是「在 H3 生成视频上持续跟踪主体」，不是判据。judge 必须从视频自身做检测/关联；proxy 只提供相机标定、时间轴与自车状态补偿。

另有 FlowTracker 在 Waymo 前视真实视频上的实现验证：8 条中 6 条可用，横向误差均值 0.030 个车宽、最大 0.079 个车宽；两条失败分别是完全跟丢与切到更大目标，可由宽度比检出。这是图像空间跟踪的可行性证据，**不是** H3 端到端的召回/FPR。

### 零样本 VLM（S2，221 条）

| 输入 | 模型 | 召回 | 误报 |
|---|---|---|---|
| 整帧 contact sheet | Qwen3-VL-8B | 5/76 = 0.066 | 16/145 = 0.110 |
| 整帧 contact sheet | GPT-6-Luna | 16/76 = 0.211 | 8/145 = 0.055 |
| 胶片条（方案 1） | Qwen3-VL-8B | 4/76 = 0.053 | 10/145 = 0.069 |
| 胶片条（方案 1） | GPT-6-Luna | 3/76 = 0.040 | 5/145 = 0.034 |

分场景（整帧）：Qwen cut_in 2/46、cut_out 2/20、lateral 1/10；Luna 12/46、3/20、1/10。分场景（胶片条 1）：Qwen 0/46、2/20、2/10；Luna 1/46、1/20、1/10。

Qwen 的「车道内位移」只有 0.0（158 次）、0.1（5）、0.2（38）、0.4（15）、0.5（1）、0.8（4）六种取值，判定几乎是 `shift ≥ 0.4` 的确定性函数，不是测量。Luna 的 221 条里 194 条 SHIFT 精确为 0，首末位置被写成同一个常数 0.5。

方案 1 的胶片条本身有缺陷，所以这轮不构成对「裁到目标车」的证伪：

- 窗口宽 `cw = clip(max(14·bw, span_x + 6·bw), 720, 1800)`，上界 1800 已接近原宽 1920；近处车 `bw ≈ 100 px` 时 `14·bw` 就是 1400，抽检目标车在 480 px 面板里只有约 30 px。
- 窗口被直接 resize 到 480×240，宽高比不等于 2:1 时会被压扁，车道线斜率随之变形。
- 红框跟踪用「中心距之和 ≤ 250 px」贪心匹配，部分片段后几帧跳到另一辆前车。

### 按框归一化胶片条 + 检测器几何（方案 1b）

YOLO11m 逐帧检测，裁剪窗宽 = 3 倍框宽（目标车尺寸恒定、道路相对滑动），并按 1 车宽间距画青色标尺。几何判据用已知车宽消掉深度：`y = (u − cx0) · W / w`，`cx0 / f` 按 drive 用 GT 拟合一次，逐帧不用任何 GT。

统一在实际产出胶片条的 192 条片段上（69 正 / 123 负；29 条因主体框覆盖率 < 0.5 未出图）：

| 方法 | 召回 | 误报 |
|---|---|---|
| 几何判据 A1（GT 轨迹） | 66/69 = 0.957 | 23/123 = 0.187 |
| 检测框 + 拟合车宽（无 GT） | 0.855 | 0.269 |
| 检测框 + GT 深度 | 0.908 | 0.166 |
| 整帧 Luna | 16/69 = 0.232 | 8/123 = 0.065 |
| 归一化胶片条 Luna | 12/69 = 0.174 | 24/123 = 0.195 |
| 整帧 Qwen3-VL-8B | 5/69 = 0.072 | 14/123 = 0.114 |
| 归一化胶片条 Qwen3-VL-8B | 0/69 = 0.000 | 0/123 = 0.000 |

**几何消融（221 条口径）**：名义车宽 1.8 m、不平滑 = 0.750 / 0.303；按类拟合有效车宽（car 2.35、bus 2.45、truck 2.90 m）并 5 帧中值平滑 = **0.855 / 0.269**；改用框高 = 0.842 / 0.262。相机拟合 f = 1188 / 1920 / 1825 px，cx0 = 955 / 913 / 975 px，投影残差中位 8–16 px。深度相对误差 −0.27（10–20 m）、−0.19（20–35 m）、−0.17（35–50 m）、−0.19（50 m+），即框宽系统性偏大约 20%。

三条结论：

1. **VLM 的失败方式变了但没消失。** 归一化后 Luna 真的在逐块读数（SHIFT 分布 −2.0…+2.0，101/192 非零），但把一次真实变道读成 0.5–1 车宽，而实际约 2 车宽——**读数被压缩 2–4 倍**。阈值后处理救不回来：`|SHIFT| ≥ 0.5` 是 0.435 / 0.358，`≥ 1.5` 掉到 0.058 / 0.065。
2. **Qwen3-VL-8B 完全塌缩**：192 条输出一模一样（0.0 / 0.0 / 0.0 / no），加标尺、加裁剪都无效。
3. **几何误差可完整归因到深度**：同一批检测框，深度用真值时 0.908 / 0.166 已逼近 GT 轨迹；换成框宽反推就掉到 0.855 / 0.269。检测器像素定位够用，缺的只是逐帧一致的单目深度。
4. **Luna 的读数是「往右走」的先验，不是测量**：68 条正 SHIFT 对 23 条负 SHIFT；69 条正样本里只有 37 条给出非零符号，其中符号正确 23/37 = 0.622——右移 19/25 = 0.76，左移只有 4/12 = 0.33。被判 yes 的 12 条里 `|SHIFT|` 中位 1.0 车宽。

### 检测器 + DA3 米制深度（221 条）

DA3METRIC-LARGE（0.35B，Apache-2.0），逐帧单图推理，`process_res=504`、stride=2（每条 40 帧），在主体框内取深度中位数。

**关键点**：模型输出是 canonical depth，模型卡写明「乘焦距才是米制」。直接用会得到错误结论——DA3 深度系统性偏小、偏小比例与焦距成反比（三个 drive 比值 0.767 / 0.539 / 0.551，IQR 仅 ±7%），判据被压成「几乎从不报警」，看起来误报只有 0.117，其实是坏的。

按 `z_metric = z_da3 · f / c` 换算（c 由 GT 反推，逐 drive 926 / 1040 / 1004，全局取 982）后误差归零：

| GT 距离档 | 中位相对误差 | \|误差\| 中位 | n |
|---|---|---|---|
| 10–20 m | +0.049 | 0.052 | 1,164 |
| 20–35 m | +0.015 | 0.058 | 2,788 |
| 35–50 m | −0.021 | 0.070 | 1,854 |
| 50 m+ | −0.092 | 0.107 | 1,331 |

| 深度来源 | 召回 | 误报 |
|---|---|---|
| DA3 原始（未换算） | 38/76 = 0.500 | 17/145 = 0.117 |
| **DA3 × f / 982** | **63/76 = 0.829** | **20/145 = 0.138** |
| GT 深度（上限） | 66/76 = 0.868 | 22/145 = 0.152 |
| 框宽反推（上一轮） | 64/76 = 0.842 | 35/145 = 0.241 |

DA3 版本的误报（0.138）甚至低于 GT 深度版本（0.152），因为深度序列比逐帧 GT 更平滑。分场景召回：cut_in 39/46、cut_out 15/20、lateral 9/10。

判定规则可调出不同工作点：

| 规则 | 召回 | 误报 |
|---|---|---|
| 幅值带 [1.8, 6.5] m | 0.829 | 0.138 |
| 离散车道序号 + 幅值带 | 0.789 | 0.124 |
| 离散 + 两端序号稳定 + 幅值带 | 0.645 | 0.048 |
| 仅离散车道序号 | 0.829 | 0.207 |

**结论：深度不再是瓶颈。** 检测器 + DA3 + proxy 焦距已经能替代 GT 轨迹进 loop。

### 车道线路线的天花板（纯 GT，不用任何感知）

| 判据 | 召回 | 误报 |
|---|---|---|
| 连续 \|dx\| ∈ [1.8, 6.5] m | 73/76 = 0.961 | 25/145 = 0.172 |
| 离散车道序号变化 | 75/76 = 0.987 | 29/145 = 0.200 |
| 离散 + 两端稳定 | 68/76 = 0.895 | 24/145 = 0.166 |
| 离散 + 幅值带 | 73/76 = 0.961 | 22/145 = 0.152 |

误报上限 0.152 已经不优于 DA3 的 0.138，而真实车道线检测器还会引入自己的误差；加上预训练车道线模型（TuSimple/CULane）与 1920×600 行车记录仪的相机几何差异大，零样本迁移风险高。另 7/220 条片段车道序号变化 ≥2，跨多车道很少见。

图像空间车道线实验进一步确认了可见性问题：24 条冒烟片段里多条两侧覆盖率只有 0.00–0.25。这条路线已按决策停止，脚本保留仅用于复现「为什么不继续」。

## 结论

1. **几何判据被严重低估。** S1 上它像废物，是因为 Waymo 缺车道几何、且正样本由它自己筛出；换到人工标注后有 95% 召回。问题在数据源，不在判据。
2. **车流补偿必须删掉。** 修正标注后它两项都不占优（0.95/0.15 对 0.95/0.12），且 5 条误报里 4 条由它凭空造出。
3. **原表 19% 的误报里有 7 条是标注缺口，不是判据错。** 真实 FPR 降到 12%，已在 15% 门槛之内。剩余误报中 10 条来自跟踪 ID 串车、8 条来自弯道与自车变道。
4. **VLM 不适合当「测量器」。** 8B 零样本输出的是伪装成数字的二分类；Luna 整帧也只到 0.232 / 0.065。加标尺后确实开始逐块读数，但幅度压缩 2–4 倍、且右向偏置明显。**VLM 只能做粗粒度分类，米制/尺度读数必须由几何给出。**
5. **Waymo perception 不适合这类评测**：无车道几何，且正样本无法与判据解耦。后续评测统一走 PREVENTION。
6. **PREVENTION 的标注在这 3 个 drive 上不是完全可信**：145 条随机负样本里藏着 7 条真实变道（4.8%）。它仍是最好的可用源，但指标要按这个比例打折扣。
7. **当前可进 loop 的路线**是「检测 + DA3 + proxy 焦距」：0.829 / 0.138，不需要 GT、不需要标定之外的任何东西；要压误报可用 0.645 / 0.048 的高精度档。
8. **未关闭的关键验证**是合成域：S2 是真实视频，DA3 与检测关联在 H3 生成视频上是否同样工作尚未验证；`c=982` 跨相机、跨 `process_res` 的稳定性也要重测。

## 构建期踩到的坑

- `lanes.txt` 的 `c0` 确是米制车道线偏移，但检测不全：跨线帧上主体与最近检测线距离中位 0.28 m，仅 41/57 落在 0.5 m 内。车道归属改用固定 3.5 m 车道宽模型。
- `labels.txt` 的框是**原始像素坐标**，对画面去畸变会让框整体偏出车体，渲染必须用原始像素。
- 网络中断会让 `ffmpeg` 无限等待，渲染卡死在 152/221；`extract_frames` 已加 `-rw_timeout` 与 `subprocess` 超时。
- 中断渲染会留下 `moov atom not found` 的坏 mp4，评测脚本已加逐条容错与断点续跑。
- Luna 批次里 17 条负例因临时磁盘写满在两次尝试后为 null，覆盖率为 204/221。
